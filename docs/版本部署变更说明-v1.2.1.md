## 一、本版解决的两个反馈

### 1. 本地存储路径可以「选择文件夹」

v1.1.0 只能在「存储位置」里手输绝对路径，路径长、容易打错。v1.2.1 加了目录选择器：

- 「存储位置 → 书库目录」右侧新增 **浏览…** 按钮，点开是完整的选择器：
  - 左栏：**磁盘**（枚举真实存在的盘符）+ **快捷位置**（当前书库 / 插件数据 / 用户目录 / 文档 / 桌面 / 下载）；
  - 右栏：当前目录的子文件夹列表、上一级、路径面包屑；
  - 支持**新建文件夹**（建完自动进入）；
  - 底部显示所选目录，并标出「该目录不可写」；点「选择此文件夹」即切换书库（旧书库自动迁移）。
- 为什么不是系统选择器：宿主把插件跑在 `sandbox="allow-scripts"` 的 iframe 里，`showDirectoryPicker()`
  会被 Chrome 直接拒绝（`SecurityError: Sandboxed documents aren't allowed to show a file picker`）。
  因此改由原生后端读盘（新增 `storage/listDirs` / `storage/mkdir`），插件自绘选择器——不依赖任何浏览器 API。

后端配套约束：

- `storage/listDirs` 只返回目录，过滤隐藏项与系统目录（`$RECYCLE.BIN`、`System Volume Information`、`AppData` 等）；
- 不传路径返回盘符 + 快捷位置，作为浏览起点；已在根目录时 `parent` 为空，不能一路往上翻；
- `storage/mkdir` 拒绝含 `/ \ : * ? " < > |` 的名字与 `.` / `..`，避免越权建到别处；
- 只接受绝对路径，相对路径直接报错。

### 2. PDF「导入后还是乱码」

这一版按「能不能复现」把可能的原因逐条查完，而不是再猜一次：

| 检查项 | 结论 |
| --- | --- |
| 打包产物里有没有 CMap 数据 | 有。`ui/assets/index-*.js`（3.9MB）内含 168 个 CMap 键（`UniGB-UCS2-H`、`GBK-EUC-H` 等） |
| 真实 PDF 在真实宿主里渲染 | 正常。本机 8 份真实 PDF（职称证书、扫描件、Word 导出、5.5MB 大文件）逐个导入：画布有内容、文本层无替换符、汉字数与原文一致 |
| 中文 CMap 是否真的起作用 | 起作用。`pdf-cmap-check` 用「缺 CMap 对照组」验证：去掉内联 CMap 后中文确实丢失，说明这条链路是有效的 |
| 书架标题是否乱码 | 这是一类真实隐患（见下），但本机样本未命中 |
| 单页渲染失败 | 之前是**静默留白**，用户看到的正是「一片空白/不正常的字」——本版改为显式报错 |

据此本版补了三处会直接表现为「乱码 / 打不开 / 白页」的短板：

1. **单页渲染失败不再静默**：以前某页 `page.render()` 抛错只会 `console.error`，画布已填白 → 用户看到一张白纸。
   现在该页会显示「这一页渲染失败：<原因>」，整份文档打不开时也有一条显式提示。
2. **加密 PDF 给出可照做的提示**：`PasswordException` 转成「该 PDF 已加密，需要密码才能打开」，
   而不是抛一个英文异常名。
3. **元数据标题乱码检测**：不少国产工具写进 PDF 的 `Title` 其实是 GBK 字节，被按 PDFDocEncoding
   解码后变成 `Âí¼Ì¾¼` 这类拉丁补充字符乱飞的形态，直接显示在书架上就是「乱码」。
   现在检测到这种形态就退回文件名；`Author` 同理清洗。

> 若装上新包后**仍有**某份 PDF 乱码，请把那份 PDF 直接发我（或截图告我：是页面上的字形不对、
> 还是书架上书名不对、还是整页空白）。现在有了逐页报错，界面上会直接写出失败原因，定位会快很多。

## 四、部署步骤

1. 关闭当前正在运行的插件页面（旧 bundle 会被缓存，务必重新加载）。
2. 用 `release/com.mjj3610.ebook-1.2.1-windows-x64.dbxp` 覆盖安装（同 id 升级，书库不受影响）。
3. 打开「工作台 → 电子书阅读器」，进「存储位置」确认：
   - 当前存储位置显示为真实磁盘路径，且标记「可跨会话」；
   - 书库目录右侧有 **浏览…** 按钮。
4. 若之前手动填过路径，迁移逻辑不变：切到已有书库的目录直接使用那里的数据；目标目录为空则把当前书库复制过去，原目录保留不删。

## 五、已知限制

- 系统目录选择器在沙箱里仍不可用（Chrome 限制），所以选择器是插件自绘的；它只能选目录，不能选文件（导入仍走拖拽 / 文件选择）。
- 跨平台发包：本包只含 `bin/windows-x64/backend.exe`；macOS / Linux 需在对应平台各执行一次 `npm run pack`。
- 加密 PDF、扫描版 PDF 的 OCR、AZW3 的 HUFF/CDIC 压缩仍不支持，均有明确提示。
- 未内嵌字体的 PDF 会用系统替代字体绘制，字形可能有细微差异（控制台有一条 `Cannot load system font` 提示），不影响阅读。
