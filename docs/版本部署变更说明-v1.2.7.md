# v1.2.7 变更说明

> 基线：v1.2.5（`62a93cf`）→ 本版 `1.2.7`
> 主题：修掉「选不中文字 → 加不了高亮与笔记」。PDF 与文字流（EPUB / TXT / FB2 / RTF）两条链路各有一个独立根因。
> v1.2.6 是只修了 PDF 的中间版本（本地 review 包，未发版），本版把文字流那条一起修掉。

---

## 1. 用户报告

第一张截图：PDF 停在一张表格页，右侧笔记面板空空如也，底栏提示「选中正文文字即可高亮」；文字怎么选都没有浮条。以前存过的高亮，重新打开这本书也不见了。

第二张截图：EPUB 正文里**文字已经选中了**（蓝色选区清清楚楚），浮条依然不出现，笔记加不进去。

两条链路，两个不同的 bug。

## 2. 根因 A：PDF 的容器查不到自己

`src/core/render.ts` 的 `collectText()` 负责把容器里的文字收成一条文本流，是选区、高亮、引文定位三件事的共同底座：

```ts
const container = root.querySelector('.book')
```

而 PDF 阅读器的文本层元素**自己**就带 `.book` 类（`<div class="text-layer book" />`）——`querySelector` 只找子孙、**不匹配自身**，于是 `container` 恒为 `null`，`collectText()` 永远返回空文本。

| 下游 | 表现 |
| --- | --- |
| `readSelection()` | `end <= start` → 恒返回 `null` → 浮条不出现 |
| `applyNotes()` / `wrapQuote()` | 空文本里找不到引文 → 老高亮一条都画不出来 |
| 笔记面板 | 没有任何 note 被写入，所以是空的 |

EPUB / TXT 当时不受这一条影响：它们的 root 是 ShadowRoot，正文确实在**子节点**的 `.book` 里。

**修法**

```ts
const self = root as Partial<Element>
const container: ParentNode | null =
  typeof self.classList?.contains === 'function' && self.classList.contains('book')
    ? (root as ParentNode)
    : root.querySelector('.book')
```

判定放在 `querySelector` 之前，两条路径都成立。同时把高亮样式抽成 `buildMarkCss(prefix, textColor = 'inherit')`，`buildBookCss` 复用之，配色只留一处定义；`PdfReader` 挂载时注入 `.text-layer` 专用样式表（文字保持透明、背景给足），卸载时移除——PDF 文本层的字是 `color: transparent`，只给背景色看不出任何变化。

## 3. 根因 B：Shadow DOM 的选区被报成「折叠在宿主上」

文字流阅读器把正文挂进 `.page-host` 的 shadow root，`readSelection(root)` 里用的是：

```ts
const selection = window.getSelection()
if (!root.contains(range.startContainer) || !root.contains(range.endContainer)) return null
```

Chrome 对 shadow 内的选区，`window.getSelection()` 只给一个**折叠到宿主元素**的范围。实测（真实宿主，`origin=null`）：

| 取法 | startContainer | 是否在 shadow 内 | 选区矩形宽度 |
| --- | --- | --- | --- |
| `window.getSelection()` | `DIV`（宿主） | **false** | **0** |
| `ShadowRoot.getSelection()` | `#text` | **true** | 361 |

所以 `root.contains(startContainer)` 恒为 false → 恒返回 `null`。截图里「文字明明选中了却没有浮条」就是这一条。顺带一个隐性 bug：即使放行，浮条位置也会是 `(0,0)`，因为矩形来自那个宽度为 0 的折叠范围。

**修法**：新增 `activeSelection(root)`，先试 `ShadowRoot.getSelection()`（Chrome 已实现），再退回 `window.getSelection()`，**取第一个落在 root 里的选区**；`readSelection()` 直接返回 `{ text, start, end, rect }`，矩形与偏移来自同一个选区。`FlowReader` 与 `PdfReader` 的 `onMouseUp` 不再各自去问 `window.getSelection()`。

```ts
function activeSelection(root: ParentNode): Selection | null {
  const candidates: Array<Selection | null> = []
  const shadow = root as ShadowRoot & { getSelection?: () => Selection | null }
  if (typeof shadow.getSelection === 'function') candidates.push(shadow.getSelection() ?? null)
  candidates.push(window.getSelection())
  for (const selection of candidates) {
    if (!selection || selection.rangeCount === 0) continue
    const range = selection.getRangeAt(0)
    if (root.contains(range.startContainer) && root.contains(range.endContainer)) return selection
  }
  return null
}
```

PDF 的文本层在 light DOM，没有 `getSelection`，自然退回 `window.getSelection()`，不引入回归。

### 附：测试脚本自身的一个坑

`host-note.mjs` 第一版把 `frame.evaluate` 里的 `getBoundingClientRect()`（**iframe 内**坐标）直接喂给 `page.mouse`（**主页面**坐标），拖拽点整体偏移到宿主外壳上，选中的其实是宿主 UI 的文字，出现假阴性。现已统一改用 `locator.boundingBox()`（Playwright 已换算到主页面坐标系）。凡是在 iframe 里做鼠标操作的脚本都要注意这一条。

## 5. 怎么加高亮 / 笔记（操作路径）

1. 打开书，**按住左键拖过要标记的文字**（同一页内可跨行；PDF 还能跨单元格）。
2. 抬手后文字上方浮出操作条：**四个色点**（直接高亮）、**批注**、**翻译**、**复制**。
3. 点色点 → 立即高亮；点「批注」→ 弹窗写正文 + 选颜色 → 保存（提示「笔记已保存」）。
4. 右上角**笔记按钮**打开面板：按章节（PDF 按页）分组，显示引文 + 批注 + 时间；点条目跳回原文，垃圾桶删除（二次确认）。

已知限制：**跨页拖选**（PDF 第 7 页拖到第 8 页）不会出浮条——选区两端落在两个独立的文本层里，`readSelection` 会判为无效，需要分两次选。扫描件（无文本层）选不中。
