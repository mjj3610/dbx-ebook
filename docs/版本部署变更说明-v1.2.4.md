## 一、问题：TXT 这类文字格式「显示不全、翻不了页」

现象（用户截图）：一本 1.1 KB 的 PowerShell 脚本 TXT，单页模式下页面几乎全空，
只在左边缘能看到几行被截断的文字；点下一页没反应，进度却显示「本章 100% / 全书 100%」。

受影响的不是某一种格式，而是**所有走文字流排版的格式**（TXT / RTF / FB2 / MOBI / AZW3 /
DOCX / Markdown / HTML / EPUB），只是短文档不足一页时不翻页，所以平时看不出来。
PDF（独立渲染器）与漫画（图片流）不受影响。

### 复现与定位

用用户那份文件在浏览器里量了一下几何（窗口 1280×860，整章 3 列）：

| 状态 | 纸面位置 x | 纸面宽度 | 屏幕上看到什么 |
| --- | --- | --- | --- |
| 第 1 页 | 230 | 820 | 正常 |
| 第 2 页 | **-646** | 820 | 纸面左移 876px，只剩右侧 174px |
| 第 3 页 | **-1522** | 820 | 纸面完全在视口外 → 全空 |

三处独立的 bug 叠在一起：

1. **位移作用在纸面本身**。`.page-host` 既是裁剪窗口又是正文容器，翻页时把
   `translate3d()` 打在它身上，于是**整张纸被推出阅读区**——第 1 页之后屏幕就是空的。
   正确做法是纸面固定不动，位移只作用于 Shadow DOM 内的正文容器 `.book`。
2. **双页从来没生效过**。判定写的是
   `mode === 'double' && width >= 900`，而 `width` 已经先被 `Math.min(stage.clientWidth, 820)`
   截断成 ≤ 820，条件恒为假 —— 选「双页」实际仍是单列，用户看到的就是「双页只显示一页」。
3. **测量时位移还在生效**。`host.scrollWidth` 会把「被平移的正文包围盒」算进去，
   平移越远 `scrollWidth` 越小。于是**一重排（改字号、缩放窗口、切模式）列数就被低估**，
   后面的内容永远翻不到 —— 这是「显示不全」的另一半原因。

另外两个观感问题：

- 正文**贴着纸面边缘**，没有内边距（纸面宽度正好等于正文列宽）。
- `text-align: justify` 遇到长 URL 会把行内空格撑成巨大间隙（`curl      -Uri      "https://…"`），
  看起来像排版错乱。

## 二、修复

| 位置 | 改动 |
| --- | --- |
| 结构 | 新增 `.page-frame` 作为纸面（背景、阴影、内边距 32/26px），`.page-host` 退化为固定不动的裁剪窗口 |
| 位移 | `column-*` 与 `translate3d()` 全部移到 Shadow DOM 内的 `.book`，一步 = 一屏宽 + 栏间距 |
| 双页判定 | 用**扣掉 padding 与纸面内边距后的可用宽度**判断，双列时每列宽 `min(820, (可用宽 - 56) / 2)` |
| 测量 | 读 `scrollWidth` 前先 `transition:none` + 位移归零，测完再落位；重建（非用户翻页）不播动画 |
| 尺寸 | 一律用 `clientWidth/clientHeight` 扣掉 padding，窄屏不再溢出被裁 |
| 排版 | 新增 `looksLikeCodeLine()`：长 token / 缩进 / 命令名 / 高 ASCII 且带语法符号的行标 `p.code`，改左对齐 + 任意位置断行，消掉 justify 撑开的空隙 |

1280×860 下的实测几何：

| 模式 | 可用宽 | 单列宽 | 纸面宽 | 纸面 x |
| --- | --- | --- | --- | --- |
| 单页 | 1280 − 96 − 64 = 1120 | 820 | 884 | 198 |
| 双页 | 1280 − 96 − 64 = 1120 | 532 | 1184（532×2 + 56） | 48 |
| 窄屏 390 | 390 − 40 − 36 = 314 | 314 | 350 | 20 |

## 四、部署步骤

1. 关闭插件页面（旧 bundle 会缓存，务必重新加载）。
2. 用 `release/com.mjj3610.ebook-1.2.4-windows-x64.dbxp` 覆盖安装（同 id 升级）。
3. 打开任意 TXT / EPUB：单页、双页都应显示完整的一屏，左右按钮与触屏滑动都能翻页。
4. 阅读进度、书签、笔记不需要迁移。

## 五、已知限制

- 代码行判定是启发式：单靠缩进与符号识别的排版偶尔会与相邻段落对齐方式不一致。
- 双页在可用宽度 < 900px 时自动降级为单页（横向空间不足，两列会挤）。
- 章节之间仍是「翻到章末再进下一章」，不提供跨章连续滚动（滚动模式可以）。
