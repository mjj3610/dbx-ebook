## 一、问题：某类中文 PDF 整页「每个字都错成另一个字」

现象（用户截图）：一份 161 页的周报 PDF，正文里**每个汉字都变成另一个固定的汉字**，
数字、英文、标点、图片却完全正常；同一份文件用 Edge 打开是好的。

- 不是缺 CMap：包里 168 个 `.bcmap` 全部内置，其他中文 PDF 也正常。
- 不是编码问题：这一页的**文本层**（复制/选中/听书用的那层）取出的是正确文字
  「阿特斯阳光电力集团股份有限公司宿迁电池 周报——W01」。
- 不是字体没加载：pdf.js 注册的 FontFace 状态是 `loaded`。

真正的定位过程（用这份文件在浏览器里逐步做对照实验）：

| 检查 | 结果 |
| --- | --- |
| 字体字典 | `/Subtype /CIDFontType2` + `/Encoding /Identity-H` + `/CIDToGIDMap /Identity` + 内嵌 `/FontFile2` |
| pdf.js 给每个字分配的字形码 | 一部分落在私用区（`U+102FB5` 等），另一部分**退回成原始 CID**（如 `U+39B3`） |
| 直接画「私用区码位」 | 画出来的是**别的字** → pdf.js 重建这份字体时字形索引错位 |
| 直接把「真实 Unicode 字符」交给系统字体画 | 完全正确 |

也就是说：pdf.js 会把内嵌字体重新打包（重建 `cmap`/`loca`）再交给浏览器，
而这类由 WPS / 福昕 导出的「子集 + Identity CIDToGIDMap」字体在重建后
**码位与字形对不上**，同时有一部分字形被判定为空、直接退化成「把 CID 当汉字画」。
两类错误叠在一起，就得到「每字都错成另一个字、且大量字不显示」的效果。
Chrome / Edge 自带内核对这类文件走的是原始 glyph id，所以不受影响。

## 二、修复：自动识别 + 字体兼容模式

1. **自动识别**（`detectFontMappingIssue`）：打开 PDF 后取第 1 页的绘制指令，
   逐个字形检查 pdf.js 分配的码位——内嵌字体正常时一定落在私用区
   （`U+E000–F8FF` 或 `U+100000+`）；一旦某个字形既不在私用区、又与它自己的
   Unicode 对不上（说明退回了原始 CID），就记一个「可疑字形」。
   可疑字形占比 ≥ 10% 且样本 ≥ 8 个，判定这份文件需要兼容模式。
   正常 PDF（含无内嵌字体的中文 PDF、西文 PDF、扫描件）不会命中——
   无内嵌字体时 pdf.js 直接用 Unicode 作字形码，与 CID 恒等，不算可疑。
2. **字体兼容模式**：确认需要兼容后，把 PDF 里内嵌的字体程序「摘掉」再重新解析
   （`stripEmbeddedFontPrograms`）。摘除方式是**等长改名**
   （`/FontFile2` → `/ZontFile2`，`/FontFile3`、`/FontFile` 同理），
   字节长度不变，交叉引用偏移量因此仍然有效，文件照常解析；
   而且只改「键名 + 数字 数字 R」这种字典语法，不会误伤二进制流里偶然出现的同样字节。
   摘掉字体程序后，pdf.js 只能走 ToUnicode → 真实 Unicode → 系统字体这条路，
   于是**字是对的、位置是对的**，只是字形来自系统字体（与原文略有差异）。
3. **告知用户**：进入兼容模式时，阅读区底部出现一条可关闭的提示
   「这份 PDF 的内嵌字体无法正确映射，已改用系统字体显示……」，
   避免用户以为「字形变了 / 又出 bug 了」。
4. **导入时的封面**也走同一套判定，所以书架上不会存下一张「书名全是错字」的封面图。

为什么不做字体索引修正：那段逻辑在 pdf.js 的 worker 里重排字形表，
要改只能给 pdf.js 打补丁，升级版本即失效；「摘字体 + 系统字体」是唯一
不依赖内部实现、且对所有同类文件都成立的退路。

## 四、部署步骤

1. 关闭正在运行的插件页面（旧 bundle 会被缓存，务必重新加载）。
2. 用 `release/com.mjj3610.ebook-1.2.3-windows-x64.dbxp` 覆盖安装（同 id 升级）。
3. 打开那份 PDF：应能正常阅读，底部出现兼容模式提示（可关掉）。
4. 之前导入过的这类 PDF：入库时已经存了坏封面，**删掉重新导入**即可刷新封面；
   阅读本身不受影响（每次打开都会重新判定）。

## 五、已知限制

- 兼容模式下字形来自系统字体，与原文排版细节会有差异（字宽、字重）。
- 判定只看第 1 页；如果一份文件只有后面的页有坏字体，不会触发兼容模式。
- 加密 PDF、扫描版 OCR、AZW3 的 HUFF/CDIC 压缩仍不支持，均给出明确提示。
