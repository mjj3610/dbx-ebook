## 一、本版解决的两个反馈

### 1. 书籍与笔记真正落盘到实际磁盘路径（对齐 AI.MD 笔记的做法）

v1.0.0 的书库放在浏览器 IndexedDB 里，在 DBX 沙箱（`sandbox="allow-scripts"`、`origin === null`）中
IndexedDB 直接被禁用，`showDirectoryPicker` 也会抛
`SecurityError: Sandboxed documents aren't allowed to show a file picker`，于是只能退化成内存存储。

v1.1.0 按官方规范补上**原生 Sidecar**（`[backend] language = "go"`）：

- 后端以当前用户权限运行，直接做文件 IO；前端通过 `window.dbxPlugin.invoke()` 走 JSON-RPC 调用。
- 书库布局（可在界面上改根目录）：

  ```
  <书库目录>/
  ├── library.json          书单、笔记、阅读设置、书籍文件名索引
  └── books/
      ├── book_xxx.epub     书籍原文，文件名 = 书籍 id + 真实扩展名
      └── book_yyy.pdf
  ```

- 默认位置：宿主下发的 `DBX_PLUGIN_DATA_DIR/library`；未下发时（本地调试）回退到用户配置目录。
- 「存储位置」弹窗里直接显示绝对路径、目录内书籍文件数，并提供输入框改路径、一键恢复默认；
  换目录时后端会先把旧 `library.json` 与 `books/` 复制过去（目标目录已有书库则直接使用，不覆盖）。
- 大文件按 512KB 分块读写；文件名只接受纯文件名，`../` 一律拒绝。

实测（官方本地宿主 + 真实磁盘，`scripts/host-disk.mjs`）：

```
书库目录：C:\Users\<user>\AppData\Roaming\dbx-ebook\library
library.json 已写入
books/book_5d79….txt 与原始内容逐字节一致
刷新宿主后书架仍有书，且不出现「仅本次会话」提示
```

存储优先级变为四档：**原生磁盘 → 用户选的文件夹 → IndexedDB → 内存**，
任一档不可用都会自动降级，界面文案如实说明当前落在哪一档。

### 2. PDF 中文乱码 & 其他格式同步排查

**PDF 根因**：中文 PDF 普遍使用 CID 字体 + 预定义 CMap（`UniGB-UCS2-H`、`GBK-EUC-H`、`Adobe-GB1-UCS2` 等）。
pdf.js 默认要 `fetch(cMapUrl)` 下载 `.bcmap`，而沙箱 CSP 是 `connect-src 'none'`，请求必然失败，
CID→Unicode 映射全断，整页文字变成乱码。

**修复**：把 168 个 CMap 与 10 个标准字体（Foxit `.pfb`）以 base64 内联进 bundle，
用自定义 `CMapReaderFactory` / `StandardFontDataFactory` 直接从内存返回字节 —— 全程零网络请求。
`scripts/pdf-cmap-check.mjs` 用一份手写的「Type0 + UniGB-UCS2-H」中文 PDF 做了正反对照：
内联 CMap 时能还原「电子书阅读器 / 书名号《测试》」，去掉 CMap 则复现乱码。

**其他格式同步排查结果**（逐项修）：

| 格式 | 问题 | 处理 |
| --- | --- | --- |
| RTF | ① 跳过 `\fonttbl` 后 `skipDepth` 停在 0，被 `>= 0` 误判为「仍在跳过」，**字体表之后的整篇正文全丢**（真实 RTF 都带字体表，等于 RTF 书籍空白）；② `\'hh` 硬编码 GBK，忽略 `\ansicpg`；③ 裸高位字节按 UTF-8 解得到替换符 | 修正跳过状态的收尾、按 `\ansicpg` 选码表（936/950/1251/1252/65001…）、高位字节交给同一码表缓冲、`\uN` 后正确跳过 `?` 或两段 `\'hh` 替身 |
| FB2 / FBZ | `file.text()` 强制 UTF-8，`encoding="windows-1251"` 的俄文书全乱码 | 改走 `decodeMarkup()`，先读 XML 声明 |
| EPUB | ① ZIP 内 XHTML/OPF 被 JSZip 强制 UTF-8 解码，GBK 包乱码；② GBK 打包时包内文件名（JSZip 按 UTF-8 错解）与 OPF href（正确解码）对不上，章节全部「找不到」 | `readZipText()` 改按文件头部声明解码；`loadZip()` 用 `decodeFileName` 还原非 UTF-8 条目名 |
| TXT / HTML / MD | 无 BOM 的 UTF-16 会被当成单字节文本；`<meta charset=big5>` 声明被忽略 | `decodeBuffer()` 增加 UTF-16 无 BOM 探测（按空字节分布）；`decodeMarkup()` 支持声明的码表，并对「声明 gb2312 实际 UTF-8」的常见错标做回正 |
| MOBI / AZW3 | 头部只允许 UTF-8 / cp1252，但不少中文书用 GBK 存正文却标 1252 | 加启发式：1252 解出大量高位字符且 GB18030 能还原出成片汉字时，改用 GB18030 |
| DOCX / ODT / CBZ | 同 ZIP 文本链路 | 统一走新的 `loadZip()` / `readZipText()` |

## 二、其他改动

1. **存储层重构**：抽出 `LibraryBackend` + `FileStore` 端口，本地文件夹与原生 Sidecar 共用同一套
   「索引 + books/」逻辑，避免两份实现漂移。
2. **落盘文件名修正**：导入时先写元信息再写文件，磁盘上得到 `book_xxx.txt` 而不是 `book_xxx.bin`。
3. **存储位置弹窗**：显示真实绝对路径与文件数、可改路径 / 恢复默认；模式高亮改为跟随「实际生效的后端」，
   选「自动」但后端是原生磁盘时高亮落在「本机磁盘」上。
4. **版本号统一**：`manifest.json` / `package.json` / 后端 `Metadata.Version` 全部 1.1.0
   （宿主要求 Sidecar 上报的身份与清单一致，否则报 `Sidecar identity or protocol does not match manifest`）。
5. **打包形态变化**：带原生后端后不再产出 `-universal` 包，改为按平台出包（当前 `-windows-x64`）。

## 四、部署步骤

1. 取 `release/com.csisolar.ebook-1.1.0-windows-x64.dbxp`，在 DBX 客户端「插件」中安装（未签名，属审查候选包）。
2. 首次打开「电子书阅读器」工作台 → 点顶部「存储位置」，确认路径为
   `…/plugin-data/com.csisolar.ebook/library`（或自定义目录），此时导入的书籍即写入该目录。
3. 验证：在该目录下应看到 `library.json` 与 `books/`；关闭再打开宿主，书单与进度仍在。
4. 升级自 v1.0.0 的用户：旧书库在 IndexedDB / 内存里，不会自动搬过来；如需保留，
   先在 v1.0.0 里「备份与同步 → 导出（含书籍文件）」，升级后「导入备份」即可。
   磁盘上遗留的 `<id>.bin` 文件仍可正常读取。

## 五、已知限制

- 原生后端只能覆盖当前平台的构建：macOS / Linux 包需在对应平台上执行 `npm run pack`。
- 宿主未下发 `DBX_PLUGIN_DATA_DIR` 时（例如 `dbx-plugin dev` 本地调试）会回退到用户配置目录，行为一致但路径不同。
- 扫描版 PDF 无文本层，仍不支持搜索与高亮（需要 OCR，不在本版范围）。
