# 商店上架指南（DBX Store）

本文是把本插件提交到官方商店（[`t8y2/dbx-store`](https://github.com/t8y2/dbx-store)）的完整操作手册。
结论先说：**提交物不是 `.dbxp`，而是一个包含两个 JSON 文件的 PR**；安装包本身由 DBX Store 审核后重新签名发布。

```
你的仓库                           DBX Store 仓库                        用户
─────────                          ──────────────                        ────
打 tag → 发布 Release              审核 + 签名 → plugins/<id>.json       装签名包
   │  CI 构建 5 平台未签名包            ▲
   └── release-candidates.json ────────┘
                                    ▲
               candidates/<id>.json ┘（本指南第 4 步生成）
```

---

## 0. 前置条件

| 项 | 要求 | 当前状态 |
| --- | --- | --- |
| 源码仓库 | 公开可审阅的 HTTPS 仓库 | 本地已 `git init` 并提交，**待你推送** |
| 许可证 | 新上架必须有 | 已加 `LICENSE`（GPL-3.0）与 `THIRD-PARTY-NOTICES.md` |
| 版本一致 | manifest / package.json / Release 标签三处一致 | 均为 `1.2.4` |
| 未签名候选包 | 由 CI 构建，**不要**用本地 `release/` 那份 | 工作流已就绪 |
| 签名密钥 | 作者不持有，也不运行 `keygen` | 无需操作 |

> 商店审核会检查：源码、Manifest、权限、候选包 SHA-256、大小、原生行为。本插件含 Go Sidecar，
> 因此每个平台都必须有对应产物；本地无法跨平台打包（CLI 会报
> `does not match build host`），所以一律交给 CI 矩阵。

## 1. 建公开仓库并推送

仓库名建议 `dbx-ebook`（`package.json` 与 `.dbx-store.json` 里已按 `mjj3610/dbx-ebook` 填好；
若用别的名字或组织，把这两个文件里的 URL 一并改掉）。

```bash
# 在 GitHub 网页上新建空仓库 dbx-ebook（不要勾选初始化 README/LICENSE）
git remote add origin https://github.com/mjj3610/dbx-ebook.git
git branch -M main
git push -u origin main
```

---

## 2. 打 tag 并发布 Release（触发 CI 出包）

```bash
git tag -a v1.2.4 -m "v1.2.4 修复文字类格式分页显示不全与无法翻页"
git push origin v1.2.4
```

然后在 GitHub 上 **Releases → Draft a new release**：

- 选择已有标签 `v1.2.4`
- 标题 `v1.2.4`，正文写变更说明（可直接用 `docs/版本部署变更说明-v1.2.4.md` 的内容）
- **点击 Publish release**（不是 Save draft——工作流只在 `published` 时触发）

发布后 `.github/workflows/plugin-release.yml` 会调用官方可复用工作流，在 5 个 runner 上各打一个包：

| target | runner |
| --- | --- |
| windows-x64 | windows-2022 |
| linux-x64 | ubuntu-24.04 |
| linux-arm64 | ubuntu-24.04-arm |
| darwin-x64 | macos-15-intel |
| darwin-arm64 | macos-15 |

CI 完成后，该 Release 下会多出：5 个 `.dbxp` + `release-candidates.json`。
（`.artifact.json` 作为中间产物在 Actions artifacts 里，不上传 Release。）

> 若某个 runner 不可用（例如组织禁用 arm 机器），删掉 `build-matrix` 里对应那一行再重新发版；
> `publish` 需要所有 build 成功，所以必须先删项，否则整体不会出资产。

---

## 3. 核对 CI 产物身份

`release-candidates.json` 里的 `plugin` 段必须与 `manifest.json` 一致（id / version / publisher / 权限集合）。
不一致说明 tag 与 manifest 版本不同步——商店签名会直接拒绝，必须改版本重新发版（**已发布资产不可覆盖**）。

---

## 4. 生成商店要的两个文件

```bash
# 首次准备：克隆商店仓库
git clone --depth 1 https://github.com/t8y2/dbx-store.git .tmp/dbx-store

# 从 Release 页面下载 release-candidates.json，放到 .tmp/ 下，然后：
npm run store:candidate -- --validate
```

脚本读 `.dbx-store.json`（展示信息）+ `release-candidates.json`（真实字节指纹），写出：

- `.tmp/dbx-store/publishers/mjj3610.json` — 发布者记录（首次上架才需要）
- `.tmp/dbx-store/candidates/com.mjj3610.ebook.json` — 候选版本，含 5 个平台的 `url` / `sha256` / `size`

`--validate` 会调用商店自带的 `scripts/validate.mjs`。看到下面这条**是正常的**：

```
Catalog contains 1 open candidate(s) awaiting DBX Store signing: com.mjj3610.ebook@1.2.4
```

这是刻意设计的红灯：未签名的候选不允许合并，等维护者签名后才会变绿。

脚本还会自动做一致性校验（id / version / publisher / package.json 版本），不一致直接报错退出，
避免手抄 SHA-256 出错。

## 5. 提 PR

```bash
cd .tmp/dbx-store
git checkout -b add-com.mjj3610.ebook
git add publishers/mjj3610.json candidates/com.mjj3610.ebook.json
# 下面这条不写 .dbxp、不写源码、不写私钥
git commit -m "Add com.mjj3610.ebook 1.2.4"
git push origin add-com.mjj3610.ebook
```

在 GitHub 上向 `t8y2/dbx-store:main` 发起 PR。PR 正文至少要回答模板里的四组问题，可直接用下面这份：
```markdown
## 插件信息

- 插件 ID：`com.mjj3610.ebook`
- 版本：`1.2.4`
- 发布者：`mjj3610`
- 源码：https://github.com/mjj3610/dbx-ebook/tree/v1.2.4
- 许可证：GPL-3.0-or-later
- 候选包：5 个平台，均来自本仓库 v1.2.4 Release，未签名

> 关于 ID 与发布者：插件 ID `com.mjj3610.ebook` 与商店 `publisher` `mjj3610` 同属作者个人账号，
> 反向域名前缀即 GitHub 用户名，不存在归属转移或公司域名借用。

## 能力（Capabilities）

- 一个 workbench 贡献点：`com.mjj3610.ebook.workbench`（电子书阅读器工作台）
- 前端 UI 运行在宿主沙箱 iframe 内，通过 Host API 与宿主交互
- 附带 Go 原生 Sidecar，用于把书籍与笔记写入用户磁盘

## 权限（Permissions）

Manifest 仅声明以下网络权限，无 host.storage / host.events 等其它权限：

- `host.network:https://api.openai.com:443` — 翻译（用户自填 API Key，OpenAI 兼容接口）
- `host.network:https://libretranslate.com:443` — 翻译（免 Key 的备用服务）
- `host.network:https://dav.jianguoyun.com:443` — 备份同步（WebDAV，坚果云）

译文与备份均只在用户主动触发时发起请求；API Key 与 WebDAV 密码只存本地，不写入导出包。

## 数据访问（Data access）

- 书籍文件：用户拖拽/选择导入后写入其指定的书库目录
- 笔记与阅读进度：与书籍同目录的 `library.json`
- 不采集遥测，不上传书籍内容

## 网络访问（Network access）

见上表三个域名；无其它出网行为，代码中不存在硬编码的上报地址。

## 原生行为（Native sidecar）

- 语言与实现：Go（仅标准库，`backend/` 目录），随平台编译为 `bin/<target>/backend.exe|backend`
- 协议：stdin/stdout JSON-RPC v1（`stdio-jsonl`），`plugin/initialize` 握手校验 id/version
- 能力范围：
  - `storage/describe|setRoot|resetRoot|listDirs|mkdir` — 书库位置与目录浏览
  - `library/read|write` — 书库索引 `library.json`
  - `book/write|read|stat|delete|list` — 书籍原文，512KB 分块传输
- 安全约束：
  - 只做文件读写，不执行外部命令、不加载动态库、不监听端口
  - 文件名只接受纯文件名，`../` 与路径分隔符一律拒绝
  - 新建目录名拒绝 `/ \ : * ? " < > |` 与 `.`/`..`
  - 书库根目录必须是绝对路径且实测可写
  - 无网络调用
- 权限模型：以当前用户权限运行，不请求提权

## 测试

- 端到端与宿主内测试共 9 套（`scripts/` 下），覆盖导入、三种排版、PDF 中文渲染、编码兼容、
  落盘逐字节校验、目录选择、后端协议；详见 README「验证」一节
```

## 6. 等待审核与签名

1. 维护者审核源码 / Manifest / 权限 / 候选 SHA-256 / 大小 / 原生行为
2. 维护者在 PR 上评论 `/sign`（或手动跑 `Sign plugin PR candidates`）
3. 工作流下载候选包、确认未签名、用仓库密钥签名，并回写
   `plugins/com.mjj3610.ebook.json`、`catalog/index.json`，删除 `candidates/` 下该文件
4. CI 转绿后维护者合并，用户即可在插件中心安装签名版

`verified` 标记由维护者填写；提交时保持 `false`，不要自己改。

### 5b.（可选）登记自动更新

如果希望以后每次发 Release 都由商店自动开候选 PR（省掉第 4–5 步手工生成），
可在同一个 PR 里往 `automation/plugin-sources.json` 的 `plugins` 数组加一条：

```json
{
  "repository": "mjj3610/dbx-ebook",
  "metadataPath": ".dbx-store.json",
  "autoUpdate": true
}
```

是否接受由维护者决定；不加也不影响本次上架，只是后续版本要重复手工流程。

## 7. 后续版本更新

```bash
# 1) 改版本：manifest.json / package.json / backend/main.go 的 pluginVersion 三处同步
# 2) 重新构建与自测
npm run build && npx vue-tsc --noEmit
# 3) 提交并打新 tag
git commit -am "chore: bump 1.2.4" && git tag -a v1.2.4 -m "v1.2.4" && git push origin main --tags
# 4) 发布新 Release（不要覆盖旧 Release 的资产）
# 5) 重复第 4–5 步，只提交 candidates/<id>.json（不再需要 publishers/ 与 .dbx-store.json）
```

规则要点：

- **已发布资产不可覆盖**，任何字节变化都必须递增版本并重新审核
- 同一版本号不能重复提交（`plugins/*.json` 里已有的版本会被拒）
- 商店展示信息（名称 / 简介 / tags / 图标）只在首次上架或主动改动时才需要更新 `.dbx-store.json`

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| CI 红：`open candidate(s) awaiting DBX Store signing` | 预期行为，等维护者签名后自动消失 |
| 校验报 `publisher 'mjj3610' is not registered` | `publishers/mjj3610.json` 没一起提交；首次上架必须包含 |
| 签名报 manifest 与候选不一致 | tag 版本 ≠ `manifest.json` 版本，改版本重新发 Release |
| 校验报 `candidate URLs must use HTTPS` | 用了 http 或本地路径；必须指向 Release 的 https 资产。CI 生成的 `release-candidates.json` 里 `url` 只有文件名，`npm run store:candidate` 会自动补成 Release 资产地址 |
| 首次提 PR 后 `Validate catalog` 显示 `action_required` | 首次向 `t8y2/dbx-store` 贡献时，GitHub 要求维护者批准才跑工作流；这不是失败，等维护者点一次即可 |
| 校验报 URL 引用了 dbx-store releases | 提交了已签名包；应提交自己仓库的未签名候选 |
| Release 里没有 `release-candidates.json` | 工作流没跑：确认是 **Publish release** 而非 draft，且 workflow 文件已推到 main |
| 本地 `npm run pack` 出的包能提交吗 | 不能。本地只能打当前平台，且商店要求 CI 产物与其 SHA-256 对应 |
| 想改 publisher | publisher 与 manifest 绑定，改它等于换归属；首次上架前定好，之后不能静默转移 |
